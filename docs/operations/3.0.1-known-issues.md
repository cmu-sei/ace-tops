# Polar 3.0.1: known issues and what is next

From a clean install of 3.0.1 on an Apple-silicon Mac (minikube, `local-minimal`), 2026-11-06. Polar came up and read Jira.
The README's **Known issues in 3.0.1** has the short form; this page has the workarounds and what is left to do.

## Known issues, with workarounds

1. **A signed change you push may not reach the agent.** The scheduler observer delivers a pushed file through a watcher
   that can stop without a word; what it reads when it starts is always delivered. **Workaround:** after
   `polar-sign ... --push`, run `kubectl -n polar rollout restart deploy/polar-scheduler-observer`, and check the agent's log
   for the new version. **Fixed** on the development branch (the observer reads the checkout again after every pull), for 3.0.2.
2. **On a Mac, a VPN can hold the cluster's connections out.** The cluster's virtual machine passes each connection to the
   Mac, so the Mac's VPN is in the path: the connection is made and TLS never answers. **Workaround:** turn the VPN off, or
   have it pass the virtual machine's traffic. `nu infra/jira-check.nu <target>` names this case.
3. **`jira-check.nu` failed on a cluster whose nodes have IPv6** (`Row number too large`). **Fixed** on `release/3.0.x`. The
   script runs from your checkout, so pulling the branch is enough; no image changes.
4. **`openssl verify` on macOS fails Polar's certificates with error 53** (`unsupported or invalid name syntax`). **Harmless:**
   macOS's `openssl` is LibreSSL, which checks the syntax of every name a certificate carries and does not accept all of
   Polar's. To check that a certificate and the CA belong together, compare the certificate's Authority Key Identifier with
   the CA's Subject Key Identifier (`openssl x509 -noout -text`).
5. **3.0.0 cannot seal any secret:** its `polar-sign` refuses every agent's escrow certificate. **Use 3.0.1**, from a clean
   install.
6. **`polar-sign` needs its once-per-container setup** before it is first used: the port-forwards, the git configuration and
   the scaffolds (README, step 8). The dev container's shell is fish: `just polar-git-config <you> | grep '^git config' | source`.
7. **Not explained yet:** piping a token from fish's `read` into `polar-sign sign` damaged the input file, which `polar-sign`
   does not write. **Prefer the seed:** put `jira_token` (with `jira_email` for Jira Cloud) in your `user.sops.yaml` before
   running `up.nu`, and it seals jira-observer's credential for you.

## To work through for 3.0.2

- **Back-port** the scheduler observer's delivery fix (issue 1), with an audit of the development branch's other fixes
  since 3.0.0.
- **Find how the input file was damaged** (issue 7), and fix or document it.
- **Find which name LibreSSL refuses** (issue 4), and give the README's Mac section a check that macOS's `openssl` passes.
